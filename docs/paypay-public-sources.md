# PayPay公開クーポンの取得範囲

調査日：2026-09-07（日本時間）。認証情報・個人のCookieを使わずに確認。

## 取得できた公開情報

- PayPay公式「スーパーPayPayクーポン」：現在のHTMLから11件のクーポンカードを抽出。店名は画像のalt属性、付与率はカード本文、クーポンIDは公式アプリへのリンクに掲載されている。すべてソフトバンク限定として扱う。
  - https://paypay.ne.jp/event/super-paypay-coupon/
- LYPプレミアム公式：外部ブラウザでもJavaScript実行後に当月の10件の店名が表示された。当月欄の期間・付与率・上限・利用回数を取得。翌月予告欄は当月に流用しない。
  - https://premium.yahoo.co.jp/benefit/coupon/paypay
- ソフトバンクの期間・上限は、2026-08-24のお知らせからリンクされた公式月次PDF（1〜2ページ）で確認した。これらの補完値はクーポンIDに限定して照合する。新IDや異なる率に古い上限を当てはめない。
  - https://www.softbank.jp/mobile/info/personal/news/service/20260824a/
  - https://www.softbank.jp/mobile/set/data/info/personal/news/service/20260824a/pdf/targetstores_aug_20260824.pdf

## 一般向け一覧・個別詳細を取得できなかった理由

公式ガイドからリンクされるPayPayクーポンマンデーの外部ブラウザ画面はHTMLをHTTP 200で取得できるが、実際の一覧データは得られなかった。通常の匿名ブラウザを使った確認では、画面自身の `getSeasonDetails` / `getCouponsForSeason` リクエストがHTTP 401になり、画面に「読み込みができませんでした」と表示された。

公式に掲載されたクーポンIDの詳細画面も、画面自身の `getCouponDetails` / `getCouponMetadata` がHTTP 401だった。共有・アプリ起動リンクがあることだけで、外部から詳細や獲得済み状態を読めるとはいえない。認証を回避する処理は追加していない。

## 修正した点

以前の取得先 `/event/jumbo-coupon/` は2022年の期間が記された古いクーポンページだった。現在の全件一覧として使わない。

`coupon-feed.json` は公式公開の会員向け情報のみを取得する。個別配信・一般向け一覧の全件・Myクーポン・獲得状態・使用済み回数・残り上限は取得していない。公開候補の検出と、利用者のクーポン獲得は別。

PayPayの候補は初期状態で順位に加算しない。「今回使える」で会員・獲得・対象決済・未使用を利用者が確認し、対象商品の支払額を入力した場合のみ上限込みの計算をする。同じ店では付与額が最大の1枚だけを使用し、複数の率を足さない。期限切れ、48時間を超える未更新データ、上限や期間が不明のクーポンは順位に加算しない。

公開ページの変更や配布の早期終了はあり得る。最終的な対象条件はPayPayアプリの表示が優先。画面の「公開掲載未検出」は「クーポンが存在しない」という断定ではない。
