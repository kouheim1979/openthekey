# 支払いチェッカー

公開先: https://kouheim1979.github.io/openthekey/

店名または現在地から店舗を選び、支払い方法を比較する静的アプリです。決済ポイントと、会計前に提示するポイントカードの特典を分けて表示します。

## 開発で維持する仕様

- ピンク・黄色・水色・緑、太い黒枠、ポップな影、「いまのお店、何で払う？」のデザインを維持します。配置や視認性の改善を理由に別のデザインへ変更しません。
- PayPayは比較設定1.5%。楽天ペイの条件達成時1.5%と同率ならPayPayを先に表示します。
- 楽天ペイと楽天ポイントカードは別表示です。提示ポイントを決済還元に含めたり、同じ進呈分を二重計上したりしません。税抜と税込の率も一律に合算しません。
- 三菱UFJカード対象店は本人指定10%（キャッシュバック相当）、Oliveは9%、三井住友カード ゴールドNLは8%で比較します。通常還元や非対象店へは適用しません。実際の適用条件・対象方式を併記します。
- 本人設定値と公式の基本率を区別して表示します（例「本人設定値（公式8%）」）。公式率は表示専用で、順位には本人設定値を使います。公式率と出典・確認日は`rates-20261102.js`にあります。
- 三菱UFJの10%は対象店合計で月5万円（16日〜翌月15日）まで。結果画面で「今期は使い切った」を選ぶと全UFJ対象店を0.4%相当で比較し、次の16日（日本時間）に自動で枠内へ戻します。
- 終了日が公表された優遇（例：ドミーの三菱UFJ優遇は2026-12-15まで）は、`paymentUntil`の翌日（日本時間）から自動で順位から外し「終了」と表示します。
- セブンの追加2.5%は連携・対象商品を確認したときだけ加算し、Olive 11.5%／ゴールドNL 10.5%で比較。セブンマイルは税抜基準の提示分として別枠に置き、ランキングへ一律0.5%を足しません。条件確認はページ内のみで、再起動時に再確認します。
- d払いは基本0.5%、dカード設定時は計1.0%、他社カード設定時はd払い自体0%。au PAY・FamiPayは通常0.5%。FamiPayバーコード、カード、QUICPayを混同しません。
- AEON Payは通常コード払い0.5%、所定の2倍対象店1.0%。イオンカードの対応だけではAEON Pay対応と判断しません。
- 未確認は非対応の断定ではありません。一方、未確認の支払いをおすすめ順位には入れません。支店・売場・レジ・商品による条件差を残します。
- 店舗更新は公式の決済対応、提示ポイント、還元率、支店差を確認し、出典をデータへ保存します。
- 横浜市都筑区、北山田〜センター北〜センター南で利用しやすい店舗を優先します。

支払いチェッカーとは独立した単体HTMLのアプリです。支払いチェッカーのファイル・SRI・ビルドには関係しません。

## 構成

- `index.html`、`app-v2.html`、`app-v3.html`: 同一の現行画面。CSSの基調を保ち、3つを同期します。
- `audit-data-20260906.js`: 基本店舗データ。
- `rates-20261102.js`: 2026-11-02（日本時間）の還元率監査。公式の基本率（表示専用）、優遇の終了日、確認日付きの出典。本人設定値は変更しません。
- `local-stores-20260907.js`: よく使う店舗の追加データ。合計155店舗・ブランド（後続の追加データを含む）。プレッセ等の公式対象サブブランドを独立して登録し、未確認のQR決済・提示ポイントを親ブランドから自動継承しません。
- `location-search-20260907.js`: 任意の現在地サービス。位置取得、同梱の店舗位置データでの端末内検索、範囲外でのOverpass通信、短時間のメモリキャッシュを担当します。
- `nearby-stores.json`: 横浜市・川崎市（南緯35.31〜北緯35.66、東経139.47〜139.79）の登録ブランド店舗の位置（© OpenStreetMap contributors、ODbL）。`scripts/build_nearby_stores.mjs`が生成し、GitHub Actions（`nearby-stores.yml`）が毎週更新します。登録店の別名と同じ規則で絞り込み、正確な一致判定・除外・支店条件はアプリ側で行います。件数が急減したときは前回のファイルを残します。
- `checker-20260907.js`: 検索、ランキング、ポイント、画面表示の生成元。`scripts/build_auto_coupon_checker.py`で公開用`checker-20260907-autocoupons.js`を再生成します。現在地サービスを読み込めなくても店名検索は動作します。
- `icons/payment-checker-v3-master.png`: 元のアイコンのフォルムを維持して描き直した原画像。ピンクの位置ピン・水色のカード・黄色の「1」・周囲の丸・角丸の黒枠を保ちます。同名の32・180・192・512px PNGをタブ、iPhoneのホーム画面、ページ見出しで使います。アイコンを直す際は、単純な別のマークへ置き換えず、この形を基に調整してください。
- `manifest.webmanifest`: 静的なアプリ情報。アイコンとともにHTMLから直接読み込み、起動時の画像生成処理には依存しません。
- `legacy.html`、`checker-20260906.js`: 以前の実装を保持。

読み込み順は基本データ → 追加データ（9月7日・9月11日・9月13日）→ 還元率監査（11月2日）→ 現在地サービス → チェッカー。追加データや還元率監査を読み込めなかった場合は、起動時に画面へ警告を出し、店名検索は残りのデータで続けます。すべて同じ公開コミットから配信します。スクリプトを変更したときは、3つのHTMLのSRI（SHA-384）とキャッシュ識別子を同時に更新してください。HTMLやJavaScriptを読み込んだ後の文字列置換で修正を重ねないでください。

## 現在地検索

初回は低消費電力の位置取得を優先し、誤差が大きい場合だけ精度を上げます。精度を上げても誤差が検索半径より大きい場合は、誤差の範囲（50m単位・最大1km）まで広げて検索し、候補を「目安」と明示して表示します（自動で店を選びません）。誤差が1kmを超える場合は検索せず、iPhoneの「正確な位置情報」の設定と店名検索を案内します。クーポン情報の読み込み完了などによる画面の再描画では、実行中の現在地検索を中止しません。位置取得はアプリ側の時計で全体4.5秒まで。範囲外の店舗通信はOpenStreetMapの公開Overpassサーバー3か所（overpass-api.de → overpass.kumi.systems → overpass.private.coffee）を順に使い、全体で9秒まで待ちます。応答が遅いときは800msごとに次のサーバーを追加し、混雑（HTTP 429等）や接続失敗のときは待たずに次へ切り替えます。最初に届いた完全な結果を使い、残りの通信は中止します。主サーバーは接続元ごとに同時2件までの制限があり、携帯回線では他の利用者と共有の接続元で断られることがあるためです。これらはアプリの待機上限で、端末実機の測定結果ではありません。

位置情報は「現在地から探す」を押したときだけ取得します。検索範囲が同梱データの範囲内に収まる場合は端末内で検索し、位置情報はどこにも送りません（公開サーバーの混雑の影響も受けません）。範囲外または範囲の端では、Overpass APIへ約10m単位に丸めた地点を送り、丸め誤差は検索半径を10m広げて補います。画面の距離は端末内の正確な位置で計算します。地図上の店名は単語単位で登録店と照合します（別名は単語の先頭から一致、英字の別名は単語の途中で終わらないこと）。「自販機」「東急」のように地図の店名には一般的すぎる別名は`osmIgnoreAliases`、誤一致する語は`excludeTerms`で店舗ごとに除外します（`rates-20261102.js`、2026-11-01のOpenStreetMapデータ全件で確認）。直近30秒の位置と、範囲を覆う直近10分の店舗データをページ内メモリで再利用します（公開サーバーへの負荷と失敗を減らすため）。ページを閉じると消えます。店名検索・店舗選択・中止・ページ移動で処理をキャンセルし、遅れて届いた結果で画面を上書きしません。

## イオン株主優待

イオン・イオンスタイルの直営売場について、確認済みのAEON Pay・現金にのみ優待を加算します。決済分と優待分の内訳を表示します。返金率は1・2・3・4・5・7%から選択でき、今回は使わない（0%）にもできます。初期3%は仮設定と画面に明示し、選択後は端末の設定として保存します。株数を推測して確定しません。家族カードとの半年100万円枠や対象外条件は詳細に掲載しています。

マルエツ・ミニストップ・ウエルシア等へイオン優待を自動適用しません。マルエツのWAON POINTは税抜200円で1ポイントの提示分として別表示します。

## 確認と公開

```sh
node --check checker-20260907.js
node --check local-stores-20260907.js
node --check rates-20261102.js
node --check location-search-20260907.js
python3 scripts/build_auto_coupon_checker.py   # 公開用JS・3つのHTMLのSRI・バージョンを再生成
node --test tests/regression.cjs
node scripts/test_coupon_runtime.js
python3 scripts/test_public_coupons.py
python3 scripts/test_coupon_browser.py          # 実ブラウザ（Chrome）でiPhone相当の縦横画面を確認
```

公開用の`checker-20260907-autocoupons.js`は生成ファイルです。直接編集せず、`checker-20260907.js`と`scripts/coupon_runtime.js`を直してからビルドしてください。

GitHub Actions（coupon-auto）は、どのブランチでも検証を実行しますが、クーポンデータのコミットとpushはmainで実行したときだけ行います。作業ブランチへのpushで未確認の変更がmainへ入ることはありません。

テストは実際の配信スクリプトをDOM・イベントの代替環境と仮想時計で実行し、全店舗の表示、還元率、同率順、提示ポイントの二重計上防止、公式率と本人設定値の区別、優遇の終了日、三菱UFJの5万円枠、Vクーポンの獲得確認、クーポンの期限・上限・古いデータ・通信タイムアウト、優待、位置取得失敗、通信遅延、キャンセル、キャッシュ、SRIを確認します。実機GPSやブラウザの見た目の確認とは区別してください。

公開用の変更は、最新mainを親にした1つのコミットへまとめます。他の更新を上書きする強制更新はしません。GitHubへの書き込み成功と、同じコミットの「pages build and deployment」完了を確認してから、公開済みと案内してください。
